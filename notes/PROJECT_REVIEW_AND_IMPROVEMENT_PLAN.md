# Quiet UK project review and improvement plan

Review date: 11 September 2026. Scope: local source code, tests, configuration, national output inventory, existing QA and Phase 2C results, and selected official data-source documentation. This review does not change the acoustic pipeline or regenerate its outputs.

**Recommendation**

Keep the existing England Phase 1 output as a versioned baseline. First strengthen reproducibility and source-state handling, then deliver an England candidate-area explorer with explicit uncertainty. Continue sub-threshold modelling as a separately validated research programme. Do not make a national Phase 2 raster the next milestone.

The existing work is stronger than a starter project in its acoustic arithmetic, tiling, recovery workflow and research transparency. Its central limitation is evidence: accurately reproducing a censored strategic noise map does not establish how quiet a place feels, or reliably distinguish two places below the reporting cutoff.

**What I verified**

- The project's own virtual environment passes all 42 tests in 8.24 seconds. The default system Python cannot collect the full suite because geospatial dependencies are missing; the project environment works.
- The current England directory contains 1,498 tile GeoTIFFs, and all 1,498 manifest records are marked complete.
- The saved national QA reports 13,086,924 land cells, no missing tiles, and no structural gaps or overlaps. I inspected that report and the current inventory; I did not repeat the complete national raster audit or independently measure acoustic accuracy.
- The Phase 2C audit table shows 91.33% of regional OS-link records using `global_median_all_dft` and 5.77% directly matched. These are experiment-window figures, not national coverage estimates.
- I reproduced three additional behaviours using temporary synthetic data: the Lden selector accepts `Road_All_Lnight`; the tile validator accepts an airport fraction of 999; and splitting a 10 km road at a 5 km query boundary changes the finite-line feature by the equivalent of 0.609 dB. These demonstrations leave production data untouched.

**Strengths to preserve**

Energy-space combination and aggregation are correct for the stated censoring assumptions. Keeping censored fine cells in the lower-energy averaging denominator is particularly important. The production path sensibly omits an airport-inclusive upper bound when the threshold is unknown. Atomic output replacement, retry history, deterministic tile scheduling, land masking, spatial holdouts and transparent reporting of imputation are valuable foundations. The national QA already uses tile-wise processing and disk-backed arrays for statistics: retain that approach.

These are risks in future runs and uncovered edge cases, not evidence that the frozen national tiles are corrupt.

**Architecture proposal**

Use a modular Python application with a small command-line interface and durable file-based products. There is no demonstrated need for microservices or a distributed scheduler at this scale.

The dependency flow should be: source catalogue and acquisition → normalised rasters/road tables → acoustic computations → validation and immutable release → candidate areas/routes → map products.

Separate responsibilities into `sources`, `grid`, `acoustics`, `pipeline`, `validation`, `research` and `products`. Extract shared IO, feature preparation and censored-model utilities from the historical Phase 2B module, because Phase 2C currently imports its private helpers and acquisition workflow. Preserve old experiments with explicit model versions and baseline outputs rather than copying whole modules for each new phase.

Define a validated configuration containing country, reference year, metric, thresholds, source-domain rules, grid, model version and paths. Resolve paths once relative to the configuration or project root. Put runtime dependencies into package metadata, lock a tested Python/dependency environment, and move pytest into development dependencies. Add continuous integration for synthetic tests and a tiny offline integration fixture; run live service canaries separately so service outages do not masquerade as code regressions.

Each release needs a machine-readable band dictionary, source catalogue, checksums, configuration identity, coverage mask, QA summary and limitations. Make the current four-band product the documented contract. The README's earlier three-band pilot description, proposed fields and later four-band national implementation should be clearly distinguished. `road_rail_upper_db` is not an upper bound on the airport-inclusive `combined_reported_lower_db`.

For distribution, keep analytical rasters in EPSG:27700. Produce separate map display assets and candidate-area vectors. A static map backed by published tiles and a small candidate index is a reasonable first product; introduce a database/API when user queries require it. Source details, date and uncertainty should be visible for each selected area.

**Efficiency plan**

Measure before choosing worker counts. Record elapsed time, peak memory, downloaded bytes, request attempts, cache hits and road/receptor pair counts for urban, rural and coastal tiles. Compare baseline and changes on identical inputs.

1. Fix download granularity first. The existing national audit records 466 HTTP 504 errors out of 483 historical errors. Persistent validated per-source retry caches and endpoint-aware backoff target evidenced wasted work. Retention can be bounded: keep inputs through successful tile publication, and archive source snapshots needed for released products.
2. Reuse road geometry indexes and emission arrays. `build_phase2c_features` creates a tree and `_energy_pairs` creates another. Precompute segment endpoints/lengths once, batch receptors, vectorise the numerical segment kernel, and cache geometry-only contributions where practical. Preserve the corrected radius rule and verify equivalence before adding parallelism. The current indexed GeoPackage loader should stay.
3. Avoid computing outputs that are immediately discarded. The tile pipeline calls aggregation twice on identical lower/upper energy arrays and builds an object-valued dominant-source array that its four-band export does not use. Add an energy-only path, reuse buffers and retain precision tests before reducing accumulation precision.
4. Replace the full-memory mosaic. On the saved mask extent, a four-band float64 rectangle alone is about 1.20 GB; loading all 1,498 100×100 input tiles adds about 0.48 GB before occupancy arrays and conversions. Windowed output avoids this scaling pattern.
5. Build overviews deliberately. Numeric dB layers must not silently acquire arithmetic-average acoustic summaries. Use energy-space aggregation for analytical overviews, explicit fraction/mask policies, and separately labelled visual resampling for display. GDAL offers COG creation and overview controls, but these do not automatically implement acoustic semantics. [GDAL COG documentation](https://gdal.org/en/stable/drivers/raster/cog.html).
6. Use a coarse national screening grid and refine promising regions/paths. Do not evaluate the expensive road model at every 10 m England receptor merely because the source raster is 10 m. Set the resolution from the product question and demonstrated accuracy.

These are expected opportunities, not benchmarked speedup claims. A useful first optimisation target is at least a twofold reduction in feature-generation time on the fixed research sample, with equivalent output under the agreed tolerance and lower peak memory; revise that target after profiling.

**Model and ranking improvements**

The recorded complete Phase 2C model improves Lden holdout RMSE from 7.813 to 6.969 dB, but reported-cell MAE near 40–42 dB remains 6.724 dB. This does not support precise ordering of quiet places a few decibels apart. Validate improvements against simple distance/road-class and censor-frequency baselines, with nested geographic model selection and untouched final regions. Bootstrap regions or corridors, rather than treating nearby pixels as independent replicates.

Test traffic linkage, speed, terrain and propagation changes as separate ablations on the same receptors, source support radius and folds. Include radius sensitivity. Preserve uncertainty from traffic attribution and out-of-domain inputs, rather than treating model disagreement as a calibrated confidence interval.

The bounded Tobit constrains the mean with softplus; its Gaussian intervals can still extend below zero. A zero-dB floor is a modelling assumption, not a universal physical lower limit. Decide whether the objective is a bounded mean or a bounded distribution and document it consistently. Use a numerically stable log-CDF likelihood rather than clipping tiny probabilities where feasible.

The research runner's neighbourhood target means are arithmetic means of reported dB values. They can serve as explicitly labelled reported-cell diagnostics, but they are not neighbourhood energy-equivalent levels and omit censored locations. Replace them with energy bounds and reported fractions for acoustic evaluation. Also make representative/balanced sample membership explicit: the current union gives overlaps to the representative sample while computing balanced weights from the original balanced draw. Add an overlap case before using balanced diagnostics as population estimates.

For a first user product, extract contiguous candidate zones using documented connectivity and minimum area, joining components across tile boundaries. Show area, conservative road/rail band, aviation evidence/unknown state, source coverage, access and source year. Preserve ties at the 43.010 dB road/rail censor floor; many locations are acoustically indistinguishable in Phase 1. Additional access or size ordering should be labelled as such.

Later add fine-grid intrusion statistics, reported fraction by source and a quiet-core measure. A 100 m block's mean can hide a noisy road edge. Offer broad confidence-qualified categories before a precise national rank. Homes and walking routes should have different criteria: annual 4 m strategic noise is not a direct estimate at a house facade, bedroom or walker's ear height.

**Suggested delivery sequence**

Estimates are planning ranges for one experienced developer and assume existing inputs remain available. They exclude substantial fieldwork, procurement and hosting costs.

| Stage | Indicative effort | Deliverable | Exit condition |
|---|---|---|---|
| 1. Integrity and reproducibility | 5–8 working days | Source-state contract, build fingerprint, strict metric selection, shared semantic validation, run lock, dependency lock and targeted regression tests. | Wrong metrics, incompatible resumes, corrupt values and concurrent starts are rejected; all existing tests pass; frozen outputs remain unchanged. |
| 2. Efficient published baseline | 4–7 days | Source-level retries/cache, profiling report, land-aware windowed mosaic/COGs, metadata and aligned documentation. | Intentional sea gaps pass, missing land fails, acoustic summaries agree with tile values, and memory/request savings are measured. |
| 3. Candidate-area prototype | 5–10 days | England candidate zones with access and uncertainty, plus a map-ready catalogue or small explorer. | Cross-tile areas join correctly, censor-floor ties remain visible, unknown aviation is explicit, and sample candidates receive geographic/access review. |
| 4. Bounded research iteration | 2–4 weeks | Corrected support-radius integration, traffic attribution/imputation experiment, terrain/speed ablations and untouched-region evaluation. | Improvement over simple baselines is demonstrated with geographic uncertainty estimates; quiet-boundary errors and failure regions are reported. |
| 5. Independent validation and expansion decision | Schedule after pilot | Measurement protocol, independent validation set and decision on claims, current-year scenarios and wider UK coverage. | Predetermined calibration/ranking criteria pass for the intended use. A failed gate leads to narrower claims or further research, not automatic national rollout. |

Start measurement feasibility planning during stages 1–2 because access, equipment and seasonal coverage may take longer than coding. The most valuable near-term deliverable is a reproducible, honest England candidate explorer supported by the existing baseline and a clear route to better evidence.
